# docs/

- `ui-architecture.md`: how the server-rendered UI is put together (shell,
  dialogs and side panels, the overlay loader, job status endpoints).
- `assistant.md`: design of the in-app assistant (tools, confirmation,
  audit, provider handling). `assistant-knowledge.md` is the help text the
  assistant itself reads (`app_help` tool).
- `adr/`: architecture decision records (SQLite without an ORM, rules
  plus a human review queue, one process with an embedded scheduler,
  hosted SERP providers, bring-your-own-key AI, scope).
- Security: see [`../SECURITY.md`](../SECURITY.md).

Images referenced from the main `README.md`. All of them show the synthetic
"Jordan Ashworth" demo (see `DATA.md`). None show real data.

- `demo.gif`: a short walkthrough (onboarding guide, dashboard home, diff,
  review queue, evidence snapshots).
- `screenshots/*.png`: full-size 1280x800 captures of `/onboarding`, `/`,
  `/diff`, `/review`, and `/evidence`.

All of them are generated by `scripts/capture_demo_screenshots.py`, which
seeds a throwaway database with `scripts/seed_demo_data.py` (the same seed
`make run` uses), serves it locally with the scheduler off and the
local-demo opt-out `ALLOW_NO_AUTH=1` (no account, 127.0.0.1 only), and
captures the pages with headless Chromium. Re-run it
after any UI change so the images keep matching what a fresh `make run`
shows:

```
.venv/bin/python scripts/capture_demo_screenshots.py
```
